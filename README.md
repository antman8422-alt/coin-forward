# coin-forward

L1(1H 구조판) 신호를 **앞으로** 쌓는 기록기. GitHub Actions가 매시간 돌면서 신호·거래·결과를 CSV로 커밋한다.
과거 630일 분석(`analysis/coin_quiet_alone.py`)과 **같은 규칙·같은 태그**라서 두 결과를 그대로 나란히 비교할 수 있다.

목표: "조용한 장에 혼자 튀는" 신호(★T = |BTC 48h| ≤ 3% 이고 같은 1H 봉 동시 신호 1개)가 나머지보다 나은지 실시간으로 확인.

## 설치 (한 번만)

1. GitHub에서 **새 저장소** 만들기 (예: `coin-forward`, Private 권장). 기존 상보 저장소와 분리.
2. 이 폴더 파일 전부 업로드 (`.github/workflows/hourly.yml` 포함 — 숨김 폴더라 빠지기 쉬움).
   웹에서 올릴 때: *Add file → Upload files* 에 폴더째 끌어놓기.
3. 저장소 **Settings → Actions → General → Workflow permissions → Read and write permissions** 선택 후 Save.
4. **Actions 탭 → hourly-logger → Run workflow** 로 첫 실행.
   - 초록 ✔ 이고 `report.md`, `data/`, `state/` 가 커밋되면 성공. 첫 실행은 우주 계산 + 72시간 소급이라 3~5분.
   - 빨간 ✖ 이면 로그의 "기록" 단계 메시지 확인 (BingX가 GitHub 서버 IP를 막는 경우 여기서 드러남).
5. 이후 매시 7분(UTC)에 자동 실행. 할 일 없음.

## 파일

| 파일 | 내용 |
|---|---|
| `report.md` | 요약 — 청산 거래 성적(전체 / ★T / 나머지 / 조용·시끄 / 동시 신호 수별), 2슬롯 시뮬, 보유 중, 최근 15건, 이번 주 우주 |
| `data/trades.csv` | 실제 진입한 거래 (종목당 1포지션). 열린 거래는 매 실행 진입부터 다시 계산해 청산되면 `closed` 로 바뀜 |
| `data/signals.csv` | 우주 안의 모든 ▲now 신호 (진입 안 한 것 포함 · `taken`, `skip` 사유) — 추가만 됨 |
| `data/runs.csv` | 실행 기록 (처리한 봉 수, 실패, 소요 시간) |
| `state/state.json` | 마지막 처리 봉, 주별 우주 명단 |
| `core.py` | 신호·관리 규칙 (과거 분석과 동일 · **고치지 말 것**) |

### 주요 열 (trades.csv)

- `entry_kst` 진입 시각(30분봉 종가 · KST) · `ep` 진입가 · `stop0` 초기 손절(30분 6봉 스윙저점) · `stop_pct` 손절 거리
- `exit_kst` `exit_px` `reason`(손절/본절/트레일/시간) · `ret` 결과 %(비용 0.1% 차감) · `ret_raw` 비용 전 · `R` 배수 · `hold_h`
- 보유 중: `stop_now` 현재 손절선(3×ATR 트레일 반영) · `unreal` 평가 % · `hiR` 최고 도달 R
- 태그: `btc48` BTC 48h % · `quiet` (|btc48|≤3) · `nsig` 같은 1H 봉 동시 신호 수 · `alone` (=1) · `crowd` (≥4) · **`T` (조용 & 혼자)** · `rs48` 종목−BTC 48h %p · `reb60` 60일 저점 대비 반등 % · `sl1h` 1H 24봉 스윙 기준 SL% · `vmult` 거래량 배수 · `reb30` 30봉 반등 %
- `backfill=1` 첫 실행 때 소급한 72시간 — 성적 집계에서 빠짐

## 규칙 (고정)

- 데이터: BingX 무기한 선물 USDT (과거 630일 분석과 같은 소스)
- 우주 B: 매주 월요일 00:00 UTC, 직전 7일 1H 거래대금 상위 30 (7일 봉 ≥120, 스테이블·NC 제외, 후보 = 현재 24h 거래대금 상위 120)
- 진입: 1H · 48봉 돌파 · 량 80봉 평균 × 1.5 · 24봉 스윙 SL 4~10% · 30봉 저점 대비 반등 ≥5% · ▲now(30분봉 종가 기준 첫 충족)
- 관리: 30분 · 초기 손절 6봉 스윙저점 · 3×ATR14 트레일 · 24시간 안에 1R 못 가면 시간청산
- 1H 봉이 **완성된 뒤**에만 처리 → 미확정 신호 없음. Actions가 늦거나 멈춰도 다음 실행에서 빠진 시간(최대 14일)을 순서대로 처리
- 우주 종목 20% 넘게 데이터 실패 → 그 실행은 저장 안 하고 다음 실행에서 같은 구간 재처리

## 참고

- 합성 데이터로 한 시간씩(가끔 최대 30시간 멈춤 포함) 707회 돌린 결과가 과거 분석 코드의 일괄 계산과 거래 243/243건 일치, 동시 신호 수 100% 일치, 결과 % 차이 0.0001% 미만.
- 트레이딩뷰 BingX 현물 차트 알림과는 소스(현물 vs 선물)·명단이 조금 달라 신호가 100% 같지는 않다. 기록기의 목적은 "같은 잣대의 표본"을 쌓는 것.
- 저장소에 매시간 커밋이 생기므로 GitHub의 "60일 무활동 시 예약 실행 중지"에 걸리지 않는다.
